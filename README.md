# Threat Info Service

REST-сервис для хранения и выдачи информации об угрозах. Угроза идентифицируется MD5-хешем файла.

- **Go**, стандартный `net/http`
- **PostgreSQL** через драйвер `pgx`
- **OpenAPI 3.0**: спецификация в [`api/openapi.yaml`](api/openapi.yaml), типы и каркас сервера генерируются `oapi-codegen`
- **Docker**: сервис и база запускаются одной командой

## Запуск

Нужны Docker и Docker Compose.

```bash
docker compose up -d --build
```

Сервис доступен на `http://localhost:8080`. Таблица в базе создаётся автоматически из [`migrations/`](migrations/).

Остановка:

```bash
docker compose down       # данные сохраняются
docker compose down -v    # данные удаляются
```

> SQL из `migrations/` выполняется один раз, при создании базы. Если миграция изменилась, пересоздайте базу: `docker compose down -v`.

## API

| Метод | Путь | Описание | Успешный код |
|---|---|---|---|
| `POST` | `/info` | создать запись об угрозе | `201` |
| `GET` | `/info/{md5}` | получить угрозу по MD5 | `200` |
| `PUT` | `/info/{md5}` | заменить информацию об угрозе | `200` |

### Модель

Исходная модель из задания (`md5`, `name`) расширена полями, которые естественны для описания вредоносного файла.

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `md5` | string | да (в `POST`) | MD5-хеш, 32 hex-символа; уникален |
| `name` | string | да | название, 1–255 символов |
| `type` | enum | да | `trojan`, `ransomware`, `worm`, `spyware`, `adware`, `other` |
| `severity` | enum | да | `low`, `medium`, `high`, `critical` |
| `description` | string | нет | описание, до 1000 символов |
| `sha256` | string | нет | SHA-256 файла, 64 hex-символа |
| `cve` | string[] | нет | связанные уязвимости, формат `CVE-2017-0144`, до 20 |
| `vuln_status` | enum | нет | `unpatched`, `patch_available`, `patched`, `unknown` (по умолчанию) |
| `playbook` | string[] | нет | шаги реагирования, до 20 шагов по 500 символов |
| `created_at` | datetime | только в ответе | время создания, ставит сервер |
| `updated_at` | datetime | только в ответе | время последнего обновления, ставит сервер |

### Примеры

Создать угрозу:

```bash
curl -i -X POST localhost:8080/info \
  -H "Content-Type: application/json" \
  -d '{
    "md5": "d41d8cd98f00b204e9800998ecf8427e",
    "name": "Trojan.Win32.Generic",
    "type": "trojan",
    "severity": "high",
    "cve": ["CVE-2017-0144"],
    "playbook": ["Изолировать хост от сети", "Обновить антивирусные базы"]
  }'
```

Получить:

```bash
curl -i localhost:8080/info/d41d8cd98f00b204e9800998ecf8427e
```

Заменить:

```bash
curl -i -X PUT localhost:8080/info/d41d8cd98f00b204e9800998ecf8427e \
  -H "Content-Type: application/json" \
  -d '{"name": "Trojan.Win32.Generic", "type": "trojan", "severity": "critical"}'
```

### Коды ответов

| Код | Когда |
|---|---|
| `200` | успешное чтение или обновление |
| `201` | запись создана |
| `400` | некорректный MD5, невалидный JSON или данные не прошли проверку |
| `404` | угрозы с таким MD5 нет |
| `409` | угроза с таким MD5 уже существует (`POST`) |
| `500` | внутренняя ошибка сервера |

Ошибки возвращаются в формате из спецификации:

```json
{"message": "Validation failed", "details": "type must be one of: trojan, ransomware, worm, spyware, adware, other"}
```

### Поведение, о котором стоит знать

- **Регистр хешей любой.** MD5 и SHA-256 можно передавать в любом регистре, хранятся и возвращаются строчными.
- **`PUT` заменяет запись целиком**. Необязательные поля, которые не переданы, сбрасываются к значениям по умолчанию: пустое описание, пустые `cve` и `playbook`, `vuln_status = unknown`, `sha256` не задан. `md5` берётся из адреса и не меняется, `created_at` сохраняется, `updated_at` обновляется.
- **Валидация данных** выполняется в сервисе до обращения к базе. Правила повторяют спецификацию (см. таблицу модели): допустимые значения `type`, `severity`, `vuln_status`; длины строк в символах, а не в байтах; формат `sha256` и `cve`; лимиты на размер списков.

## Конфигурация

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DATABASE_URL` | `postgres://threats:threats@localhost:5432/threats` | строка подключения к PostgreSQL |
| `HTTP_ADDR` | `:8080` | адрес, на котором слушает сервис |

В `docker-compose.yml` сервису передаётся `DATABASE_URL` с хостом `db`. Учётные данные базы в репозитории учебные; для реального использования их нужно заменить и вынести в секреты.

## Структура проекта

```
.
├── api/
│   ├── openapi.yaml       # спецификация API
│   ├── codegen_config.yaml           # конфиг oapi-codegen
│   └── api.gen.go         # сгенерированный код (руками не править)
├── cmd/server/main.go     # точка входа: конфиг, сборка, запуск
├── internal/
│   ├── handler/           # HTTP-слой: разбор запроса, валидация, коды ответов
│   └── storage/           # слой данных: запросы к PostgreSQL
├── migrations/            # SQL-миграции
├── Dockerfile             # многоэтапная сборка
└── docker-compose.yml     # сервис + PostgreSQL
```

Разделение слоев: `handler` знает про HTTP и формат API, `storage` знает только про базу. Перевод между типами API и записью в базе выполняется в `handler`. Хендлер работает с хранилищем через интерфейс `ThreatStore`, поэтому его можно подменить в тестах.

## Безопасность

- SQL-запросы параметризованы, значения из запросов в SQL не подставляются.
- Входные данные проверяются до обращения к базе; в таблице дополнительно стоят ограничения `CHECK` и `PRIMARY KEY` (вторая линия защиты).
- Размер тела запроса ограничен 1 МБ.
- Подробности внутренних ошибок клиенту не отдаются, они пишутся только в лог сервиса.
- Образ сервиса собирается в два этапа и запускается от непривилегированного пользователя.

## Тесты

```bash
go test ./...
```

Табличные юнит-тесты функции валидации: корректные записи, каждое правило отдельно, граничные значения (255/256 символов в названии, 1000/1001 в описании и так далее) и многобайтовые символы.

## Разработка

Запуск без контейнера для сервиса (в Docker только база):

```bash
docker compose up -d db
go run ./cmd/server
```

Перегенерация кода после изменения спецификации:

```bash
go install github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@latest
oapi-codegen -config api/cfg.yaml api/openapi.yaml
go mod tidy
```

## Ограничения и возможные доработки

- Нет аутентификации, ограничения частоты запросов и TLS: сервис предполагается запускать в доверенной сети или за reverse proxy.
- Нет интеграционных тестов с реальной базой и тестов HTTP-хендлеров.
- Миграции применяются механизмом инициализации образа PostgreSQL, а не специальным инструментом (`goose`, `golang-migrate`).
